# Orchestrate a TODO.md stage

You are the **orchestrator**. You do not write product code yourself: you plan, launch task agents, integrate their reports and talk to the human. Keep your own context small; agents do the reading and the work.

## 1. Plan (once, at the start)
1. Read `CLAUDE.md`, the stage in `TODO.md` (every unchecked task up to the stage's ⏸ checkpoint; a finished stage is one line under "Earlier stages", with its open tasks listed there and its full text in `docs/history/`, read only when a task cites it), and skim the decisions it cites in `docs/hive.md`. Check `git status` / `git worktree list`: the main checkout must be on a clean `main`.
2. Run `scripts/ci.sh survivors`: it prints the open "Weekly mutation testing: surviving mutants" issue (`mutants-full.yml`), if any, with one comment per failed run. For the mutants it lists that no `TODO.md` task covers yet, add a task to this stage (as 9.34: each mutant, why no test catches it, the test that will, the issue number; its line numbers are from the run's commit) and ask the human to close the issue once a weekly run on `main` finds no survivors.
   Triage each survivor before writing its task, reading the source at the mutation site (never from the mutant's description alone). It is a **test gap** unless all five checks prove it **equivalent**: (1) the types involved (e.g. `x > 0` and `x != 0` agree only for unsigned `x`); (2) the mutated code is reachable (not covered ≠ unreachable: unreachability is proven from types and control flow, never from coverage); (3) the mutated value is consumed downstream; (4) original and mutant agree for every input the types allow; (5) no concrete input tells them apart after trying boundaries and type extremes (if one does, it is the test to write). An equivalent mutant is never skipped (rule 6, no `#[mutants::skip]`): the code is refactored so the mutant cannot exist (dead branch removed, redundant check folded), or it goes to the human with the five checks written out.
   Reject these: "probably equivalent" (equivalence is proven, not assumed); "`>` to `>=` is always equivalent" (only when the boundary is provably unreachable); "the suite catches it in practice" (a survivor means it does not); "the kill rate is high enough" (Hive allows no missed mutant). *(Method adapted from Trail of Bits' `mutation-testing` skill, CC-BY-SA-4.0; see `.claude/skills/stage/SOURCE.md`.)*
3. Build the dependency graph between the stage's tasks from what each task needs (code, service messages, UI pieces), not from list order. Tasks that do not depend on each other run **in parallel**; never serialize independent tasks.
   Split the tasks in two kinds, and use the heavy path only where it pays:
   - **Simple** (docs, `TODO.md`, a small fix in one area, a test or config tweak): no worktree, no branch, no CI wait (D4). Batch them into **one** agent working on `main` in the main checkout, with the local fast gates of what it touched (a commit touching `*.rs` also runs `MUTANTS=0 scripts/gates.sh`, one touching `scripts/` also `scripts/test-scripts.sh`: a red `main` turns every branch red); when it finishes, you push `main` (below). Run that agent while no merge is in flight: first, when later tasks need its work, otherwise after the last merge.
   - **Complex or parallel** (new feature, several crates, risk of conflict with another running task): its own worktree and `task/*` branch, CI green before the merge (below).
4. Find the blockers that only the human can clear and ask them **up front, together**, one question each with a recommendation (AskUserQuestion): tasks marked "⚠ Ask the human first", missing inputs (files, recordings), decisions the stage needs that `docs/hive.md` does not settle. For small implementation choices, pick a sensible default yourself and put it on the checkpoint list (step 5) instead of asking.
5. Tell the human in one short message: the waves (which tasks run in parallel), the defaults you chose, and the dependencies agents are expected to add (CLAUDE.md rule 3 — name each one and why). Then start without waiting, unless something above is a real blocker.

## 2. Run
- Launch every ready complex task at once: `Agent` with `subagent_type: general-purpose`, `isolation: worktree`, `run_in_background: true`. The prompt is: "Read and follow `.claude/skills/stage/task-brief.md` first", the task id and name, the decisions it cites, **what already exists on main that it must reuse** (APIs, files — taken from earlier reports), the orchestrator defaults that apply, and the specific scope/tests you expect. Tasks the human does (recordings, reviews) are not delegated.
- The simple tasks' agent: `Agent` with `subagent_type: general-purpose`, no isolation. Its prompt is the same, plus: "skip the brief's Worktree setup and its CI and merge steps: commit each task straight to `main` in the main checkout after the local gates of what it touched; never push".
- When an agent reports a finished task, verify the report instead of trusting it (`verification-before-completion`): the branch's diff (`git diff --stat main...<branch>`) matches what it claims, and the CI run URLs are green on its tip. Then run the reviewers on the branch in parallel, each with the task id and branch: `gate-integrity-reviewer`, `code-reviewer` (task fit and correctness against the `TODO.md` task and the `docs/hive.md` decisions it cites) and, when the diff touches `crates/hive`, `crates/hive-protocol` or `src-tauri`, `security-reviewer`. A Critical or Important finding sends the task back to its agent (`SendMessage`, the agent weighs it with `receiving-code-review`); a question for the human goes on the checkpoint list.
- When an agent reports a finished task with **green CI on its branch tip** (run URLs in the report) and the reviewers raised nothing blocking, **integrate it** from the main checkout while holding the lock: `mkdir /var/tmp/hive-merge.lock`, then one of the two paths below, then `rmdir /var/tmp/hive-merge.lock`.
  `mkdir` is the lock (macOS has no `flock`): when it fails another merge holds the lock, so wait and retry; a lock left by a crashed session (no merge running) is removed with `rmdir`.
  - `main` is an ancestor of the branch (`git merge-base --is-ancestor main <branch>`): `git merge --ff-only <branch>`.
  - `main` moved: `git merge --no-ff --no-commit <branch>`. A conflict → `git merge --abort` and send the agent back with `SendMessage` to merge `main`, resolve and push again. Clean → the local fast gates of what the combined change touches (`cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test -p <each touched crate>`; when the frontend changed, `bun install --frozen-lockfile && bun run lint && bun run typecheck && bun test --coverage`): green → `git commit -m "chore(merge): <branch>"` (Conventional Commits); red → `git merge --abort` (then `bun install --frozen-lockfile` again if the branch changed `bun.lock`) and send the agent back with the failing output.
  Then, still holding the lock, push `main`: `scripts/ci.sh push` from the main checkout. Every merge, and the simple tasks' commits once their agent finishes. A branch's CI tests the mutants of its diff from `origin/main` (`mutants.yml`): while `main` waits unpushed, every later branch tests again the mutants of each task merged before it (27.6: 1271 mutants in 20 shards, about 55 min, instead of its own 306 in 13 min; the human, 2026-11-27).
  An agent is never sent back only because `main` moved. CI checks the combined result when `main` is pushed, and Finish runs the full gates on `main` once. After the merge, delete the branch once the agent's worktree is gone (`git worktree remove` / `git branch -d`; a worktree stays locked while its agent process lives). Relay a short summary to the human (what landed, gates, items for the checkpoint). Launch every task that just became ready.
- If an agent stops with a question, answer it yourself when a decision or default covers it (continue the agent with `SendMessage`); otherwise ask the human.
- If an agent dies (session restart), check its worktree/branch for partial work and resume it with `SendMessage`.
- Never read an agent's transcript file; its report is all you need.
- Keep a running "for the checkpoint" list: defaults taken (each also a `pending` row of `TODO.md`'s "Defaults ledger"), deviations from the prototype, human decisions requested, flaky tests, dependencies added outside the announced list. Save progress to memory after each merge, so a restarted session can continue.

## 3. Finish
When every task of the stage is merged (or blocked on the human): run the full gates once on `main` (`scripts/gates.sh` with `MUTANTS=0`, frontend gates, e2e), then stop at the ⏸ checkpoint with a report: what landed (task → merge commit), gate results, the checkpoint list grouped for decision, and what the human must do (e.g. update `docs/hive.md`, which agents never edit; set the ledger's statuses). Do not start the next stage. Once the human has reviewed the checkpoint, the stage moves word for word to `docs/history/` and leaves one line (and its open tasks) under "Earlier stages" in `TODO.md`.
