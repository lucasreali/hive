## Stage 18 — macOS, second pass

Created 2026-10-20 at the human's request, after v0.14.0 (Stage 17). Three research agents audited, read-only, what Stage 17 left: the service and the app on this Mac (the installed 0.14.0, the running service), the frontend in WKWebView, and the dev, CI and release flow; their findings, with evidence, are condensed into Parts A–E. Part 0 holds the adjustments the human asks for. Nothing Stage 17 did is repeated; follow-ups to its ledger rows say so. Run with `/stage 18`.

**Decisions for the human before the stage starts** (nothing below changes `docs/hive.md`; the human updates it):

- **D18.1 Release gate.** `release.yml` (`ci-green`, lines 20–52), `scripts/ci.sh green` and the release skill check only `ci.yml`, so macOS-only code can ship red. Proposal: a release needs `ci` and `macos` green on the tagged commit (or its parent for the version bump); Windows stays optional (as accepted for v0.14.0, D17.0).
- **D18.2 Terminal environment.** Terminals get only `TERM` (`terminal.rs:192`); an app started from the Finder has no `LANG`, so fish and bash run in the `C` locale (zsh is saved only by macOS 26's `/etc/zprofile`). Proposal: when `LC_ALL`, `LC_CTYPE` and `LANG` are all unset, set `LANG` from the system locale (`AppleLocale`, e.g. `en_BR` → no such POSIX locale → `en_US.UTF-8`), plus `COLORTERM=truecolor`, `TERM_PROGRAM=Hive`, `TERM_PROGRAM_VERSION`.
- **D18.3 git on a Mac without the Command Line Tools** and the login `PATH` at start (ledger 17.5). Proposal: resolve git once at start (`xcrun -f git`); missing tools stop every git call and show one explanation in Diagnostics instead of macOS's install prompt every 30 s.
- **D18.4 Privacy keys for programs run in Hive's terminals** (Hive.app is their "responsible" app). Which of `NSAppleEventsUsageDescription` (+ the `com.apple.security.automation.apple-events` entitlement), `NSLocalNetworkUsageDescription`, `NSCameraUsageDescription`, `NSMicrophoneUsageDescription` to add.
- **D18.5 A WebContent crash** reloads the page and `Link::connect` closes every terminal (`src-tauri/src/lib.rs:1004-1006`), killing the agents in them (#14, #18). Proposal: on a WebContent termination keep the terminals and let the reloaded UI reattach (service-side scrollback replay as the fallback option).
- **D18.6 Logs.** `daemon.log` lives in `$TMPDIR/hive` (`paths.rs:91`), is truncated at every start (`bridge.rs:39-41`) and the app's stderr goes nowhere. Proposal: on macOS `~/Library/Logs/Hive/{daemon,app}.log`, one previous copy kept, an app panic hook, and a dSYM per release.
- **D18.7 Data folders.** Keep `~/.local/share/hive` / `~/.config/hive` on macOS, or move to `~/Library/Application Support` with a one-time migration (ledger 17.2's `HIVE_DATA_DIR`)? Proposal: keep (no migration risk), revisit with D18.6.
- **D18.8 Distribution (#39).** Ship Intel too (`universal-apple-darwin`, ≈2× the bundle, `darwin-x86_64` in `latest.json`)? Lowest macOS supported (`LSMinimumSystemVersion` 12.0, CI tests only macOS 14)? A Homebrew tap (needs a PAT secret; with ad-hoc signing users still "Open Anyway", D17.1)? Release notes from Conventional Commits?
- **D18.9 Projects on network or cloud folders** (iCloud Drive, `~/Library/CloudStorage`, SMB/NFS/WebDAV: FSEvents misses remote changes, git can hit its 10 s limit). Warn or refuse at Add project? Proposal: warn.
- **D18.10 Mac look and keys (#23, #35, prototype).** (a) Minimum window width 800 → 640 on macOS so half-screen tiling works on a 13–14" MacBook. (b) A "System" theme following macOS dark/light. (c) New macOS keys: ⌘T new terminal in the current worktree, ⌘N new worktree, ⌃Tab / ⌃⇧Tab cycle tabs, Fn+↑↓←→ scroll the scrollback outside the alternate screen, trackpad pinch = terminal zoom, ⌘⌫ deletes in the files tree. (d) macOS overlay scrollbars and the arrow cursor instead of the prototype's always-visible scrollbars and `cursor: pointer`. (e) Delete in the files tree moves to the Trash on macOS (today "Nothing goes to a trash").
- **D18.11 Hidden-window work.** Pause the 30 s worktree health check (`health.rs:16`), the sessions (5 s), CI runs (30 s) and PR (2 min) refreshes while the window is hidden or not in front, refreshing on return (17.27's offers then wait for the return)? Proposal: pause while hidden, keep while merely unfocused.
- **D18.12 New dependencies (rule 3), each asked again at its task:** `@codemirror/search` (18.38), `@xterm/addon-unicode11` (18.39).
