## Stage 19 — Battery, memory and CPU

Created 2026-10-22 at the human's request. Four research agents audited Hive read-only: the service, the Tauri app, the frontend, and the installed v0.15.0 running on this Mac. Their findings, with evidence, are condensed into Parts A–D below. Part 0 holds the feature the human asked for. Stage 18's Part C (18.28 FSEvents latency, 18.29 the 1 s process scan, 18.30 hidden-window work, 18.31 hidden-window output) stays where it is and is **not** repeated here; tasks that build on it say so.

**Measured on 2026-10-22** (Hive up 31 h, 7 terminals, 6 agents streaming; `top -l 30 -s 4`, `footprint`; no sudo, so no `powermetrics`):

| Process | CPU avg / max | Energy avg | Idle wakeups/s | Footprint |
|---|---|---|---|---|
| WebContent | 3.5% / 4.6% | 3.9 | 10.0 | **511 MB (peak 985 MB)** |
| hive-app | 1.6% / 3.9% | 2.4 | **17.1** | 60 MB |
| WebKit.GPU | 1.1% | 1.2 | 2.5 | 136 MB |
| `hive daemon` | 1.0% | 1.1 | 2.2 | 9 MB |
| `hive bridge` | 0.03% | 0.03 | 0.0 | 2 MB |

Total ≈ 7% CPU and ≈ 725 MB, of which WebKit is ≈ 650 MB. The daemon also held 105 directory fds out of 134 (FSEvents `WatchRoot` keeps every ancestor of each watched path open). No git/gh churn was seen in 2 minutes. The numbers are under load, not idle; 19.2 sets the baseline.

**Decisions for the human before the stage starts** (nothing below changes `docs/hive.md`; the human updates it):

- **D19.1 What "Open with Default App" may open.** Today `open_in_editor` (`file.rs:144,774`) opens only text/source types (`EDITOR_EXTENSIONS`/`EDITOR_NAMES`) and refuses executables and app bundles. Proposal: Reveal works for any file or folder inside the worktree; Open works for any regular file inside the worktree except executables (exec bit), bundles and launchable types (`.app`, `.command`, `.tool`, `.terminal`, `.workflow`, `.pkg`, `.mpkg`, `.scpt`, `.applescript`, `.webloc`, `.inetloc`, `.fileloc`, `.url`, `.lnk`, `.bat`, `.cmd`, `.ps1`, `.vbs`), so images and PDFs open in Preview. Open point #15 (`docs/hive.md:392`, `opener:allow-open-path` with `**`) is out of date since `open_path` is gated by the service; the human updates or closes it.
- **D19.2 Watching group folders.** A group watches each direct subfolder as its own path (`registry.rs:91-92,173-180`, up to 1024); with `WatchRoot` each one also holds its ancestors' fds, so a group of 200 repos ≈ 1,200+ fds of the 10,240 limit (`fds.rs`), all reopened on every `follow()`. (a) One recursive watch per group folder, keeping only `<group>/<child>/.git` events (cheap after 18.28), or (b) notify's kqueue backend for the registry (the `macos_kqueue` feature: a dependency change, rule 3). Proposal: (a).
- **D19.3 Health of other spaces.** `refresh_health` covers every space's projects (`projects.rs:97-106`) every 30 s. Check only the current space's projects (others refreshed when the space is switched to)? Proposal: yes, if no view shows another space's status.
- **D19.4 Sessions list without polling.** `ListSessions` (UI, every 5 s) rescans every process and every log folder and resends up to 500 sessions (`app.rs:421`, `sessions.rs:437-470`). (a) An "unchanged" reply when the list equals the last one sent (protocol change), or (b) the service pushes the list on change (FSEvents on the projects' log folders) and the UI stops polling. Proposal: (b).
- **D19.5 The `gh` token.** Each real PR/runs fetch first spawns `gh auth token` (`gh.rs:203`). Keep the token in memory per account for a few minutes? Security trade-off (a secret held longer in the service). Proposal: no; only the git spawn of 19.8 is removed.
- **D19.6 Notification clicks.** `main.rs:290-296` waits on up to 8 notifications (`CLICK_WAITS`, `lib.rs:409-411`); `mac-notification-sys` adds a repeating 0.5 s NSTimer on the main run loop for each, until the notification leaves Notification Center (hours or days): up to 16 main-thread wakeups and XPC calls per second, window hidden or not. Likely the measured 17 wakeups/s of `hive-app`. (a) A `UNUserNotificationCenter` delegate (no polling; `macos.rs` already uses UN), (b) at most 1–2 waits, or (c) stop waiting after N minutes. Proposal: (a).
- **D19.7 The bridge on macOS.** Every byte goes daemon → socket → `hive bridge` → pipe → app (`bridge.rs:25-33`, tokio stdin/stdout through the blocking pool, 8 KB copies). On macOS the app could connect to the socket directly and keep the bridge for WSL (#14, #24). Proposal: only the 64 KiB buffer now (19.11); the direct socket after measuring.
- **D19.8 Animations while Hive is not in front.** The working icon spins forever (`styles.css:1706-1709`) and the indeterminate tab bar animates `background-position` (`styles.css:383-388`, repainted on the main thread each frame); both keep WebKit's display link at 60/120 Hz while any agent works, also in a visible but unfocused window (the "Hive beside the editor" layout). Pause them while Hive is not focused? Proposal: yes (the look in front is unchanged).
- **D19.9 Terminal scrollback.** 5000 lines by default (ledger 1.7, `store.ts:184`), every terminal kept alive: ≈ 12 MB for a full 200-column terminal, ≈ 120 MB for 10 agents; WebContent was at 511 MB (peak 985 MB). Lower the default (e.g. 2000) or keep it? Proposal: keep 5000 and measure in 19.2 first; decide with the numbers.
